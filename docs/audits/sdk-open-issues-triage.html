The six that matter, in full

#1414 — our workaround has a hole, and #1359 is the hole

We restate the three create-media-buy-request.json anyOf branches by hand in _check_anyof_branch_conditions (src/core/schemas/_base.py:2818–2898), because the generated _require_schema_required_group tests only top-level field presence. The restatement uses model_fields_set as its requiredness test, and its docstring states the convention plainly: a supplied field counts even when explicitly null.

That convention is what reopens the defect. Measured on the pin:

packages[0] = {"product_id": "prod_1", "pricing_option_id": "cpm_usd_fixed", "budget": null}

our CreateMediaBuyRequest     -> ACCEPTED
get_total_budget()            -> 0
jsonschema Draft7 over
  _schemas/3.2/media-buy/create-media-buy-request.json
                              -> 2 errors ("None is not of type 'number'", plus the anyOf)

same document with the "budget" key removed entirely
our CreateMediaBuyRequest     -> refused: "matches no accepted shape"   (workaround live)

So the absent-key case is closed and the explicit-null case is open, on the same branch, through the same validator. Downstream the behaviour is exactly what #1414 describes: the budget floor receives 0 and answers BUDGET_TOO_LOW for a request that supplied no budget. The fix is one predicate — treat a field whose value is None as not-sent for a branch test wherever the schema's declared type excludes null.

Cross-cutting question 1 — is the codegen cluster one defect?

Four of the five are one defect. #1397 is not.

The shared root cause: generation is lossy at the schema node, and the loss is silent. The generator renders each node into what pydantic can carry on a field declaration and discards every keyword that does not fit, leaving no record that anything was dropped. Each of the four is one class of discarded keyword:

  • #1409 drops the node's identity — title, the discriminator const, the required set — and substitutes its ordinal.
  • #1362 drops the node's origin — a pointer selects a type, and the generator treats it as a position needing a name, minting a wrapper per referencing site.
  • #1414 drops the node's sibling conditions — nested required, allOf, not, const inside an anyOf branch — keeping only the branch's top-level required.
  • #1359's codegen half drops adjacent constraints: a pattern beside a format: uri, and the absent/null distinction that required plus the declared type together express.

The fix shape is also single, and #1409 is already written in it: express the keyword or refuse. union_arm_names.py raises UnnameableArmError rather than falling back to a number, which is exactly what #1414 asks for in its own words — "raise at import time or emit a documented gap, rather than silently narrow the contract". Asking upstream for one generator invariant ("no schema keyword is discarded without a recorded gap") reframes four issues as one, and gives a test that cannot go stale: enumerate the keywords in the bundle, subtract the keywords the generator can express, and require the remainder to be a declared, shrinking list.

#1397 is a different thing. It is about canonical_creative.py, which is hand-written, not generated: a deliberate API-design choice to make a tolerant boundary model subtype a strict wire model. No keyword is lost. Its second axis — the top-level export not being the annotated class — is a naming question that rhymes with #1409 without sharing its mechanism, and on our pin (above) it has already moved. Grouping it with the four would hand upstream a bundle it cannot act on as one.

The proposed check (not implemented)

One small unit module, tests/unit/test_sdk_derived_populations.py, with two tests. The design constraint is that it must be derived, must assert the population is non-empty, and must be fire-probed — and, from the lesson of _known_asset_types, it must not be able to pass by deriving its expectation from the same annotation the code under test reads.

  1. Parametrized cross-artifact equality. One parameter per derived population: a dotted module attribute and the pointer into the pinned bundled JSON Schema that declares the same vocabulary. The test reads the schema document through get_named_schema_document, resolves the pointer, and asserts the derived set is non-empty and equal to (or a stated superset of) the schema's. The expectation comes from the schema and the value comes from the model, so the two cannot drift together — which is precisely why a non-emptiness assertion alone is not enough, and why computing the expectation from model_fields would be a self-derived fixture that cannot falsify.
    • _KNOWN_ASSET_TYPES → the asset_type enum under core/format.json
    • _SELECTABLE_WIRE_FIELDS → creative/list-creatives-request.json#/properties/fields/items
  2. Completeness, so a new site cannot be born uncovered. AST-scan src/ for a module-level binding whose value derives from an SDK annotation walk, and assert every file:name found appears in the parameter list. This is the one declared part, and it is the part that keeps the derived part closed: a fifth derivation site fails the suite until someone names its schema pointer. A missing pointer is a loud failure, which is the whole difference from today.

The fire probe: remove one get_args level from _known_asset_types and the _KNOWN_ASSET_TYPES case must go red at the equality assertion — then restore. Red only counts if it is red at that assertion; a failure in collection or import proves nothing about the check. Second probe: add a new module-level derivation in a throwaway file under src/ and watch test 2 refuse it.

Cost and placement: two schema document reads and two set comparisons, so it belongs in the unit suite and runs on every make quality. It also doubles as a standing #1359 parity probe over exactly the facts we depend on, rather than over all 84 tools.

What could not be verified

  • #1397's concrete case. _DeliveryCreativeManifest and revalidate_instances appear nowhere in our tree, so we have no local observation of the manifest instance the issue is actually about — only of the ProductFilters instance we reported ourselves.
  • #1404's bundle-key risk. The _pinned_fields.py string slice and resolve_bundle_key agree on all four versions present in the bundle, so the divergence is possible and not current. Stated as latent rather than measured.
  • #1418's cold-start numbers. The 127–204 ms cold versus 0.001 ms warm figures are the reporter's; not reproduced here, and not reproducible from the seller side.
  • #1414's 42/14/12 blast radius. Taken from the issue. We verified only that our one exposed model is CreateMediaBuyRequest and that the workaround is live for the absent-key case; the other 11 models were not re-counted on our local-segment pin.
  • The .root deprecation horizon. The shim warns today. Whether it is removed in 9.0 GA or later is not stated in any open issue we read, so the 12 call sites have no dated deadline.

Every measurement above was taken in a dedicated worktree against the pin named at the top. Numbers are evidence for that pin and that tree only; a different local segment of the SDK can move several of them, as #1397 and #1359 both demonstrate.
