# Known-failing storyboard-conformance checks. THIS LEDGER IS EMPTY BY DECISION.
#
# The storyboard grades every check it collects. No check is routed to xfail, so every
# conformance gap the runner measures reddens the storyboard-conformance job, and the
# job's failure count IS the gap count.
#
# WHAT AN EMPTY LEDGER COSTS. A ledger separates "a failure we know about" from "a
# failure that just appeared". With no entries there is no such separation: a new
# regression is one more red check among the rest, and only a run-to-run comparison
# (scripts/audit/compare_runs.py against the previous test-results/ report) tells the
# two apart. That is the accepted trade — visibility of the whole gap surface over
# automatic regression isolation.
#
# WHAT STILL BITES. The DE-COLLECTION signal is unaffected: an entry that resolves to
# no collected check fails the session through ledger/fitness::stale_entries, computed
# in-session by test_storyboard_conformance.pytest_generate_tests. It has nothing to
# report while the file is empty, and it is graded on synthetic ledgers by
# tests/integration/test_storyboard_ledger_fitness_real_session.py, which redirects the
# loader with STORYBOARD_LEDGER_PATH rather than reading this file.
#
# FORMAT, if an entry is ever added. One test id per line, matching a
# tests/storyboard/test_storyboard_conformance.py parametrized test keyed on
# (protocol, track, storyboard_id, step_id) from the real @adcp/sdk runner's measured
# output. The runner grades the agent once per PROTOCOL (mcp, a2a), so an entry carries
# its protocol as the first id segment; the two halves are independent ledgers in one
# file, and an mcp-only fix that leaves an a2a twin is the drift that split exposes.
# tests/storyboard/conftest.py loads the file and xfails(strict=False) exactly these
# ids; tests/unit/test_storyboard_ledger_state.py pins its exact contents, so an entry
# added here without updating EXPECTED_LEDGER fails the unit suite.
#
# Seed an entry only from a MEASURED in-network run, never from arithmetic on an older
# one. Runner-reported SKIPS (missing_test_controller, missing_tool,
# prerequisite_failed) are never ledgered — they map to a native pytest.skip() in the
# test module. Only genuine check FAILURES are ledgerable.
