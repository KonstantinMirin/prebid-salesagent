# Known-failing storyboard-conformance checks — GENUINE production gaps only.
#
# One test id per line, matching a tests/storyboard/test_storyboard_conformance.py
# parametrized test keyed on (protocol, track, storyboard_id, step_id) from the real
# @adcp/sdk storyboard runner's measured output. Loaded by tests/storyboard/conftest.py
# to xfail(strict=False) exactly these test ids — a graduation (entry no longer
# failing) or a regression (new un-ledgered failure) both fail CI.
#
# The runner grades the agent once per PROTOCOL (mcp, a2a), so every entry carries
# its protocol as the first id segment. The two halves are independent ledgers in
# one file: an MCP-only fix graduates the mcp:: entry and leaves its a2a:: twin,
# which is exactly the drift this axis exists to expose.
#
# Locked by tests/unit/test_storyboard_ledger_state.py — keep that test in sync.
#
# Runner-reported SKIPS (missing_test_controller, missing_tool, prerequisite_failed)
# are NOT ledgered here — they map to a native pytest.skip() in the test module
# instead (SB-4b Core Invariant). Only genuine check FAILURES belong in this file.
#
# comply_test_controller/pagination-integrity is the sole PERMANENT won't-fix
# family (missing_test_controller — no test controller wired for these checks).
# RFC 9421 signing entries, when ledgered, are regular shrinking genuine-gap
# entries tied to #1291 (RFC 9421 message signing epic) — NOT permanent.
#

# ============================ a2a ============================
#
# SEEDED from the same measured in-network run as the mcp half above
# (sa-67ae7993, this branch). The a2a pass graded ZERO checks:
#   overall_status=unreachable, 0 passed / 0 failed / 0 skipped, 0.9s
#   headline: "Agent unreachable — Provided Agent Card does not contain a valid
#             'url' for the service endpoint."
#
# Root cause, verified live against the e2e stack rather than inferred:
# `/.well-known/agent-card.json` (the ONLY card path the app serves — /agent.json
# and /.well-known/agent.json both 404) is an A2A **1.0** card, advertising its
# endpoint as `supportedInterfaces[0].url`. The runner's bundled A2A client is
# `@a2a-js/sdk` **0.3.14**, which reads only the A2A 0.3 top-level `url` and
# rejects the card outright. The JSON-RPC route itself is 0.3-compatible
# (`enable_v0_3_compat=True` in src/app.py) — it is only DISCOVERY that is
# version-skewed, so nothing downstream of the card is reached or measured.
#
# So this is exactly ONE entry, not an a2a mirror of the 80 mcp ones: no a2a
# storyboard has ever been graded, and inventing entries for checks that never
# ran would be the fabrication this ledger's Core Invariant forbids. When the
# card gains a top-level `url` (or the SDK moves to an A2A 1.0 client) this entry
# xpasses and the real a2a checks arrive un-ledgered, failing CI until triaged —
# which is the intended signal, and the point of grading the axis at all.
